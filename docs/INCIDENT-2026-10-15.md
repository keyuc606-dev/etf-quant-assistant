## Mitigation

Keep the original UTC cron events and add three independent five-minute
backup events per session. The existing shared concurrency group and a
readback-verified private-state reservation prevent repeated advice, including
manual dispatches. Completion reloads state so it preserves newly appended
advice, old advice, Telegram cursors, holdings and cash. A partial send/crash
leaves an ambiguous reservation and fails visibly; it is never blindly retried.
ETF V2 runs only after the first successful morning delivery.

Print Telegram message IDs for both text and attachments, and write scheduled
versus actual start time to the Actions summary. No chat ID or token is logged.
Morning runs outside 10:30–11:30 send a degradation notice without writing a
10:30 baseline, even when afternoon prices are fresh. Existing closing
after-close behavior, source fallbacks, trading-day gate and strategy rules
are unchanged.

Backup cron events reduce individual dropped-event risk. They cannot fix a
platform-wide multi-hour delay or guarantee punctual delivery. A genuinely
time-critical service needs an independent cloud scheduler/runner; this
repository-only mitigation must not be represented as that guarantee.

# 10:30 / 14:35 执行单

用户可见 Telegram 推送固定为工作日北京时间 10:30 与 14:35。GitHub Actions cron 使用 UTC，分别为 `30 2 * * 1-5` 和 `35 6 * * 1-5`，两条工作流与交易反馈共用 `account-cloud-state` 锁。

## 数据与决策边界

- 10:30：上一完整交易日日K + 当日新鲜 provisional 开高低、价格、量价 + Final Decision Engine。
- 14:35：只复核当日 `10:30_EXECUTION` 不可变基准。缺失基准时只给风险快照。
- provisional 数据不写入正式日线缓存，不参与 weekly、allocation、rebalance 或 backtest。
- `data_quality` 与 `decision_confidence` 独立。数据为 LOW 时禁止强动作；决策 LOW 默认折叠。
- 限价参考由买卖区、ATR、失效位和当前 provisional 价格确定性计算，AI 不生成数字。
- 不连接券商，不自动交易，也不假定用户的早盘订单已经成交。

## 报告对比

旧版会在 09:20 推送基于前收盘与隔夜新闻的长报告，并在 14:30 再给盘中风险检查。用户需要从大量持仓与技术说明中自行提取动作。

新版 10:30：

```text
【10:30 早盘执行策略】
1. 京东方A 000725
结论：买入｜500股≈￥2,300｜决策中｜数据高
挂单4.48–4.52｜失效/取消4.41
原因：买入区、趋势纪律、现金和仓位闸门均已通过
未成交：不追价，14:35复核。

其余24只：无明确早盘动作。
```

新版 14:35：

```text
【14:35 尾盘执行策略】
1. 景业智能 688290
结论：风险退出｜200股≈￥11,200｜决策高｜数据高
原因：失效位跌破且MA20趋势破坏
若早盘订单未成交：仅按本次更新后的区间人工复核，区间外不追价。
若已成交：请以已录入成交为准；系统不假设订单已执行。

其余：无明确尾盘动作，维持原计划/不操作。
```

## 历史兼容

旧记录不改写。旧读取路径继续兼容没有新字段的历史记录；新基准写入 `advice_session=10:30_EXECUTION`、`generated_at`、`data_quality` 和 `decision_confidence`。原 `confidence` 字段保留给旧读取方，建议 outcome 和显式成交归因定义不变。

At inspection, closing workflow had 18 runs; its latest run was October 13,
38357525588 (success). No October 14 closing run or traceback existed.
Morning run 38531645259 started at 15:56 Beijing time, although its cron is
02:30 UTC / 10:30 Beijing. It exited in the morning notification step with
`没有可验证的当日新鲜 provisional 行情，10:30执行策略不推送`.
Trade runs shown for October 14 succeeded. This does not prove a trade
message was processed; these runs may have had no incoming message.

The fetcher's existing 15:05 upper bound intentionally returns no intraday
quote after close. The notification orchestrator treated this safe rejection
as a fatal error before sending anything. There was no Python traceback or
evidence of a cloud-state, fundamental-field or Telegram regression in this
failure. The last strategy change did not change cron or this quote guard.

The minimal fix sends a no-action degradation notice without persisting a
10:30 baseline when no fresh quote exists. Closing runs arriving after 15:05
send an explicitly delayed notice, without writing closing observations.
Live market-time decisions, fetcher freshness limits, cloud blob reads and
trade handling are unchanged. Tests exercise the actual after-close fetcher
guard and orchestrator, not only the report builder.

GitHub cron is best effort. This change cannot guarantee a run at 14:10 or
repair a schedule event that GitHub has not delivered. A manual closing run
after close can safely validate cloud read, report build and Telegram sending;
it must not be represented as a reconstructed intraday trading plan.
